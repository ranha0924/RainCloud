**제어·UI·실제 sandbox 검증은 완료했으며 새 흐름의 실모델 최종 성공 검증은 미완료입니다.** 실제 QA가 누락된 회귀 테스트를 발견해 수정 요청을 전달했고, 수정 중 대표가 허용한 토큰 한도에서 실행기가 멈췄습니다. 완료/배포 완료로 표시하지 않았습니다.

레슨퀘스트가 이 컴퓨터에 없어 별도 인사 도구 저장소를 사용했습니다. 기존 회사 데이터와 원본 미완료 변경은 보존했습니다.

## 실제 모델 실행

App Server 0.153.4, `gpt-5.6-luna`, 기존 ChatGPT 로그인을 사용했습니다. 별도 API 키를 넣지 않았습니다.

업무는 한국어 인사의 공백 trim·빈 이름 방문자 처리, 입력 안내·aria-live, 회귀 테스트 추가입니다.

1. 구형 문서 예시 `readOnly.access`가 설치 버전에서 거절됐습니다. 2회 모델 시작 전 실패를 보존하고, 바이너리의 생성 스키마와 공식 권한 문서에 따라 이름 있는 `permissions` 프로필로 수정했습니다.
2. 첫 실제 PO가 자신의 역할을 전체 구현 완료로 오해해 정보 대기로 보고했습니다. 역할별 완료 의미를 보완했습니다. 이 기록을 지우지 않고 동일 실증 프로젝트에 후속 업무를 만들었습니다.
3. 후속 PO 완료 체크포인트 뒤 실행기를 실제 재시작했습니다. PO를 다시 호출하지 않고 CTO로 이어졌습니다.
4. 개발자들이 각각의 worktree에서 실제 코드 파일 2개를 수정하고 통합했습니다.
5. 300,000토큰 한도에서 306,492토큰 알림을 받아 중지했습니다. 대표의 명시적 승인 후 **이 프로젝트만 500,000**으로 올렸습니다. 완료된 PO·CTO·백엔드를 반복하지 않고 프런트엔드부터 재개했습니다.
6. QA 명령은 종료 코드 0이었으나 기존 테스트 1개뿐이었습니다. 실제 QA 모델이 요청된 회귀 테스트 누락을 확인하고 `passed=false`로 수정 요청을 전달했습니다. 검증 탭을 닫아도 QA와 수정 실행은 계속됐습니다.
7. 백엔드 수정 회차 중 다시 한도에 도달했습니다. 마지막 알림 기준 **520,054토큰**, 해당 프로젝트 **8회 모델 시도**입니다. 이후 추가 모델 호출을 하지 않았습니다. 회사 전체 설정은 1,000,000토큰으로 유지했습니다.

8회에는 최초 PO 정보 대기와 후속 업무의 중단·재개가 모두 포함됩니다. 프로토콜 진단의 모델 시작 전 실패 2회는 별도 기록입니다. 토큰 사용량은 알림 단위이므로 마지막 호출의 초과분도 그대로 기록했습니다. 금액으로 환산하지 않았습니다.

## 실제 권한과 UI

`node tests/sandbox-validation.mjs`는 모델 호출 없이 App Server `command/exec`를 사용합니다. 다른 등록 프로젝트의 canary 읽기, 회사 DB 읽기, 읽기 전용 QA의 쓰기가 모두 **EPERM**으로 차단됐습니다. 결과는 `.local/sandbox-validation/report.json`입니다.

기본 `:root=deny`만으로 Windows의 모든 외부 파일 읽기가 차단되지는 않았습니다. 등록된 다른 프로젝트와 회사 데이터에 명시적 deny를 추가하고 실제 검사했습니다. 완전한 OS 사용자/컨테이너 격리를 주장하지 않습니다.

실증 데이터로 프로젝트 전환, 목표·사용량·직원별 업무, 시작 전 범위·경로·한도 확인, 정보 대기·결정함·자료함 UI를 확인했습니다. 시작 확인 화면에서는 추가 실행을 승인하지 않았습니다. 이후 탭을 닫은 상태에서도 실행기가 진행했습니다.

## 남은 제약

최종 QA 통과·CTO 보고·대표 검토 대기까지의 **새 흐름 실모델 성공**은 아직 확인하지 못했습니다. 예산 자동 증액이나 새 프로젝트를 통한 한도 우회는 하지 않습니다. 추가 실증을 진행하려면 대표의 추가 한도 허용이 필요하며, 저장된 백엔드 수정 단계부터 재개할 수 있습니다.

나머지 보조 직무 전체의 실모델 검증, PC 부팅 자동 실행, 외부 발송/지출/배포 커넥터, 완전한 OS 격리, 외부 의존성 준비, WorkAdventure·Vercel 연동은 남아 있습니다.
