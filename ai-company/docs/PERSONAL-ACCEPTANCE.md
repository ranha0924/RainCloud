# 개인 운영 실험의 검증 기준

각 단계는 재현 가능한 테스트를 통과한 뒤 연결한다. 최종 독립 검증은 구현 함수의 자기 보고 대신 HTTP 응답, 영구 저장소, 실제 산출물과 실행 로그를 별도로 확인한다. 총점은 100점이며 85점을 **초과**해야 완료다. 미검증은 0점이고 점수 때문에 테스트 실패나 필요한 질문을 숨기지 않는다.

| 항목 | 배점 | 완료 근거 |
| --- | ---: | --- |
| 대표 창구와 결정함 | 15 | 프로젝트별 담당자, 중복 묶기, 추천·대안·영향, 승인 경계 테스트 |
| 필요한 실행팀 | 10 | CTO 분배와 선택된 개발자만 실행, 실제 인계·QA·검토 연결 |
| 명시적 개입 시간 | 15 | 시작/종료·사후 입력, 날짜 경계, 재시작, 미측정·초과 표시 |
| 목표별 성과와 품질 | 15 | 기준 버전, 증거·수용·재작업, 분모·관찰 기간 테스트 |
| 대표 화면 | 10 | 실제 브라우저에서 목표·결정·결과·시간 이동 검증 |
| 운영 개선 | 10 | 반복 근거에서 후보, 명시적 적용, 프로젝트 범위와 전후 기록 |
| 실행 제어와 보존 | 10 | 전체 중지·예산·프로젝트 격리, 기존 결과 보존 회귀 |
| 실제 레슨퀘스트 업무 | 15 | 확인된 프로젝트에서 실제 모델 분배→수정→QA→검토와 산출물 |

실제 모델을 사용하지 않는 제어 테스트는 모의 실행으로 명시한다. 원격 작업 기록 조회만으로 실제 레슨퀘스트 실행을 통과 처리하지 않는다. 기존 회사 누적 예산과 중지 상태를 유지한다. 실제 업무 실행에는 동일 사용량 원장을 사용한다.

30분은 관찰 목표이며 실행 제한이 아니다. 대표 검토 시간은 대표가 직접 기록한다. 1~2주가 지나기 전에는 장기 효과를 주장하지 않는다.

2026-09-10 사용자 추가 승인: “걍 토큰제한없애고 맘껏 써”. 회사와 이번 레슨퀘스트 검증 프로젝트의 `tokenBudget`만 `null`(무제한)로 변경했다. 다른 프로젝트의 한도와 호출·시간·재시도·중지 제어, 기존 누적 사용량은 유지한다. 해당 승인 및 변경 전 값은 실제 회사 DB의 `budgetAuthorization` 기록에 보존한다. 이 변경으로 사전 검증 기준이나 85점 초과 조건이 완화되지는 않는다.
