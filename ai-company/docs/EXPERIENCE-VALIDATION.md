# 경험·QA 비교·경력 검증 (2026-09-10)

후속 [저장 로그 기반 동점 진단](EXPERIENCE-DIAGNOSIS.md): 추가 모델 호출 없이 입력·사용량을 대조하고 검색 오류 두 건을 수정했습니다. 기존 평가 점수와 고정 조건은 보존했습니다.

## 결과

구현: 실행별 경험 기록, 피드백과 수정 실행 연결, 지침 후보/버전/검토/활성화/폐기, 범위별 검색, 공유 허가/철회, QA 활용·충돌 기록, A/B/C 조건 고정과 실행 큐, 자동 판정과 사람 검수 입력, 근거가 연결된 프로젝트별 경력 화면.

**실제 모델로 전이 과제 1개의 A/B/C 비교가 완료됐습니다. 12개 전체의 실모델 비교는 미완료입니다.** C의 성능 우위는 관찰하지 못했습니다. 합성 과제 한 개로 일반적인 성장이나 전이 효과를 주장하지 않습니다.

| 조건 | 확인된 계약 결함 | 놓침 | 오지적 | 재현 성공/지적 | 실행 시간 | 보고된 토큰 |
|---|---:|---:|---:|---:|---:|---:|
| A 기본 QA | 1 | 0 | 0 | 1/1 | 15.8초 | 28,374 |
| B + 일반 체크리스트 | 1 | 0 | 0 | 1/1 | 25.4초 | 28,717 |
| C + 허용된 경험 지침 | 1 | 0 | 0 | 2/2 | 21.8초 | 30,006 |

모델 `gpt-5.6-luna`, 체크리스트 `qa-general-1`, 과제 `auth-08`, 다른 프로젝트 `QA 경험 전이 · 별도 테스트 프로젝트`. 각 조건 1회 모델 턴, 최대 75초/20회 QA 도구 호출, 평가 누적 140,000토큰, 같은 코드/계약 스냅샷과 권한으로 고정했습니다. 실제 합계 87,097토큰입니다. 기본 지침 버전과 전체 조건 hash는 결과 JSON에 남아 있습니다.

C는 만료 동일 시각과 now 누락이라는 두 입력을 재현했습니다. 사전 판정 단위가 이 과제의 **만료 유효성 계약 결함 1개**여서 중복 가산하지 않았습니다. 원래 보고는 그대로 보관합니다. 재현 입력 수와 결함 수를 구분합니다. 각 지적은 고정 oracle와 실제 함수 반환값을 비교합니다. LLM 평가자는 사용하지 않았습니다.

사람 검수·수정 시간, 사람의 판정, 금액은 **미측정/미제공**입니다. 자동으로 숫자를 채우지 않았습니다. C의 토큰 사용량은 A/B보다 많았습니다. 시간은 각각 한 번 측정한 값으로 반복 실험 결과가 아닙니다.

## 실제 흐름

1. 별도의 연습 과제 `practice-refresh-01`을 실제 QA가 읽고 실행해 만료 경계 결함을 재현했습니다 (28,481토큰). 평가용 12개 과제와 코드 스냅샷을 분리했습니다.
2. 이 결과에 **구현 검증용 자동 피드백**을 기록했습니다. 실제 대표가 작성한 피드백이나 사람이 측정한 검수 시간으로 표시하지 않습니다.
3. 피드백에서 6단계 지침 후보를 만들고 내용을 수정해 v2를 활성화했습니다. 실증 검토자는 `implementation_validation`으로 기록했습니다. 정상 사용 시 대표가 UI에서 검토합니다.
4. 다른 테스트 프로젝트에는 원본 문서·코드·경험 내용 없이 `expiry`, `fail_closed`의 고정 일반 점검 문구만 공유 허용했습니다.
5. 전이 과제 C가 그 공유 지침을 선택하고, 어떻게 적용했는지 실제 최종 응답과 도구 호출 기록에 남겼습니다. A/B에는 경험이 제공되지 않았습니다.
6. 프로필에서 실제 업무 실적은 0건이며, 연습과 평가 기록만 집계합니다. 실행·산출물·지침·평가의 근거를 열 수 있습니다.

## 준비한 과제와 미완료 범위

총 12개: 결함 사례 8개, 정상 사례 4개. 세션 경계, 로그아웃/회수, 필수 인증 정보, 역할, 프로젝트/조직 범위, 토큰 대상 서비스를 포함합니다. 6개는 다른 테스트 프로젝트의 Portal B 계약입니다. 현재는 작은 JavaScript 계약 함수에 대한 합성 평가이며, 실제 브라우저 로그인/E2E나 운영 서비스 보안 인증을 의미하지 않습니다.

- `auth-01`: A는 결함 재현 완료, B 중단, C 미실행. A/B/C 비교 불가.
- `auth-02` 정상 사례: A/B 모두 오지적 0, C 중단. A/B/C 비교 불가.
- `auth-08`: A/B/C 모두 완료. 비교 가능한 표본 1개.
- 나머지 9개: 실제 모델 미실행. 제어/판정 테스트와 fixture 검사만 수행.

초기 60,000토큰 파일럿과 110,000토큰 정상 사례 평가의 누적 한도가 부족했습니다. 각각 마지막 알림 65,162와 118,505토큰에서 중단했습니다. 해당 고정 한도를 사후 증액하거나 중단 결과를 통과로 바꾸지 않았습니다. 마지막 호출은 알림 수신 시점 때문에 상한을 넘을 수 있습니다.

이전 자율 운영 실증의 520,054토큰을 그대로 포함하는 **동일 회사 DB/100만 토큰 한도**에서 진행했습니다. 이번 단계 12회 모델 시도, 381,019토큰을 추가해 회사 누적 **901,073토큰**입니다. 초기 도구 진단 실패·중단도 모두 포함됩니다. 기존 인사 도구 프로젝트의 500,000토큰 설정과 중단 상태는 유지했습니다. 남은 회사 한도만으로 미실행 9개를 끝낼 수 있다고 판단하지 않아 추가 모델 호출을 중지했습니다.

## 연결 오류도 기록

초기 도구 설정에서 Code Mode 호스트까지 꺼져 동적 QA 도구가 실행되지 않았습니다. 모델의 텍스트 응답만 있는 두 기록은 자동 점수를 무효화했고, 그 기록으로 만든 진단용 지침/공유도 폐기했습니다. 이후 **두 파일 읽기와 실제 함수 실행 기록이 모두 있어야 평가 점수를 산정**하도록 제어 코드를 강화했습니다.

Windows의 상위 경로 deny ACL은 다음 실행의 접근까지 방해했습니다. 시험 중 추가한 read-deny 항목을 복구했습니다. 평가의 실제 경계는 App Server의 제한된 동적 도구입니다. `qa_read`는 두 고정 파일만, `qa_execute`는 고정된 함수와 JSON 입력만 처리합니다. oracle·점수·다른 사례를 도구에 전달하지 않습니다. 셸·브라우저·MCP·앱·이미지 읽기는 비활성화합니다. Code Mode 호스트는 이 허용된 도구를 호출하는 용도로 유지합니다.

중단된 턴 3개는 `thread/read`로 다시 조회했습니다. 모두 interrupted, 최종 응답 없음이어서 복구 가능한 완료 결과로 간주하지 않았습니다. 이 확인은 모델 호출 0회였습니다.

## 재현 가능한 확인

`npm run verify`: 기존 23개 + 경험/평가 11개 + 앱별 세션 분리 1개 = **35개 테스트**, TypeScript 검사와 Vite 빌드 통과. 최종 수정 후 전체 검증을 다시 실행했습니다.

경험 기록과 실패 이력, 수정 연결, 자기 보고만으로 지침 검증 금지, 프로젝트 검색/공유/철회, 모델·스냅샷·도구·한도 고정, 뒤늦은 자료 오염 방지, 판정/중복 제거, 사용량 중단, 실제 도구 증거 누락 시 실패, 완료 턴 재사용, 여러 평가의 큐 처리, HTTP 범위 제한을 검사합니다. 테스트 모델은 명시적인 가상 어댑터이며 실모델 결과와 구분합니다.

앱의 실행 횟수는 Codex 턴 시도 수입니다. 한 턴 안에서도 도구 처리와 내부 모델 요청이 여러 번 발생할 수 있어 제공자의 API 요청 횟수와 같다고 볼 수 없습니다. 보고된 토큰과 실행 시간 한도를 함께 적용합니다.

`npm run check:experience-tools`: 모델 호출 없이 실제 App Server 설정과 도구 연결을 확인합니다. 외부 경로·다른 프로젝트/사례·임의 명령 요청이 모두 거절되고, 함수의 실제 반환값만 제공됨을 확인했습니다. OS 전체 격리를 검증했다는 의미는 아닙니다.

## 로컬 근거

- `.local/experience-validation/report.json`: 전체 결과, 조건·사용량·경력 근거.
- `.local/autonomy-live-verified/data/company.sqlite`: 경험, 피드백, 버전, 공유 허가, 평가, 실행 이벤트.
- 위 데이터 폴더의 `evaluation-workspaces/`: 조건마다 별도의 코드/계약 스냅샷.
- 위 데이터 폴더의 `evaluation-results/`: 실제 보고와 자동 검증 결과 JSON.
- `.local/experience-tool-isolation/report.json`: 모델 호출 없는 도구 범위 검사.

개인 경로와 실행 ID가 들어 있는 `.local`은 Git에서 제외합니다. 최초 앱 데이터 `.local/data`와 검증 데이터는 분리했습니다. 기존 Codex 로그인을 사용했고 별도 API 키나 새 결제는 사용하지 않았습니다.

## 사용법

`./start-company.ps1`로 웹과 실행기를 켭니다. 프로젝트를 등록하고 QA 직원을 배정한 다음 **경험 · QA 평가** 메뉴를 사용하세요.

1. 업무 등록 시 실제 업무/연습을 선택합니다. 실행 기록이 자동으로 경험에 연결됩니다.
2. **업무 경험 · 피드백**에서 경험을 선택하고 피드백, 수정 내용, 수정 실행 ID, 실제 검수 시간을 입력합니다. 비워 둔 시간은 미측정입니다.
3. **재사용 지침**에서 후보의 6단계 내용·태그·근거를 검토하고 활성화합니다. 수정은 새 버전이며 공유는 별도 허가입니다. 공유 철회는 다음 실행부터 적용됩니다.
4. **QA 비교 평가**에서 1~2개 과제와 모델·체크리스트·한도를 정하고 조건을 고정한 뒤 실행합니다. 프로젝트/회사 예산도 적용됩니다. 정상 실행은 실제 Codex 사용량을 소비합니다.
5. **경력 프로필**에서 실제 업무와 연습/평가의 근거를 나눠 확인합니다. 공개 요약은 집계의 공개 허용 표시만 저장하며 외부 게시를 수행하지 않습니다.

검증 뷰어는 현재 `http://127.0.0.1:4312/`에서 열 수 있습니다. 다시 켜려면 별도 PowerShell에서 `COMPANY_DATA_DIR`를 위 검증 데이터 경로, `PORT`를 `4312`로 설정하고 `npm start`를 실행하세요. 현재 검증 실행기는 종료되어 추가 모델 호출이 없습니다.

기본 앱과 검증 뷰어를 함께 열어도 세션이 덮이지 않도록 데이터 저장소별 쿠키 이름을 사용합니다. 두 앱을 동시에 연 상태에서 프로젝트 전환, 경력→평가 근거, 지침→원본 경험과 피드백 이동을 브라우저로 확인했습니다.

현재 과제의 추가/변형은 `server/qa-fixtures.mjs`의 신뢰하는 코드·oracle를 검토하고 새 fixture 버전으로 배포해야 합니다. UI에서 임의 코드를 판정기로 실행하지 않습니다. 모델/지침 변경 후에도 기존 평가 조건과 점수는 보존합니다. 직원 복제 기능은 기존 앱에 없어 이번에도 추가하지 않았습니다.

공식 확인: [App Server의 동적 도구](https://learn.chatgpt.com/docs/app-server), [권한](https://learn.chatgpt.com/docs/permissions). 설치된 0.153.4의 생성 JSON 스키마와 실제 응답으로 함께 확인했습니다.
