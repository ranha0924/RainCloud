# Rain Company — 독립형 AI 회사 운영 앱

프로젝트가 없어도 채용·면접·회사 대화가 가능한 로컬 앱입니다. 회사 공통 직원 프로필과 프로젝트별 목표·기억·업무·자료·권한·예산을 분리합니다. 한국어 UI를 제공합니다.

[지금 사용할 수 있는 기능과 사용 조건](docs/CURRENT-FEATURES.md)을 먼저 확인하세요.

이번 확장에는 영구 작업 큐, 독립 실행기, 자율 업무 선정, 동료 질문, QA 수정 순환, CTO 최종 검토와 대표 결정함이 포함됩니다. 레슨퀘스트의 실제 식별자 검증 버그를 PO→CTO→백엔드→QA→CTO 흐름으로 수정하고 검토 브랜치를 제출했습니다. 초기 중단 기록은 보존하며, 최신 결과는 [개인 운영 검증 기록](docs/PERSONAL-VALIDATION.md), 이전 실험은 [자율 운영 검증 기록](docs/AUTONOMY-VALIDATION.md)에서 구분합니다.

첫 화면은 **대표 화면**입니다. **목표·성과**에서 완료 기준을 정하고, **내 시간**에서 타이머·사후 입력을 사용하며, **오늘 확인**에서 결정과 결과 근거를 검토합니다. **관찰 설정**에서 1주/2주와 대표 창구를, **회의·개선**에서 안건·참여자·운영 규칙을 관리합니다. 하루 30분은 관찰 목표이며, 아직 실제 1~2주 효과는 측정하지 않았습니다.

추가된 **경험 · QA 평가** 메뉴에서 업무 경험/피드백, 검토한 지침의 검색·공유·철회, 고정 조건의 A/B/C 평가와 직원 경력 근거를 관리합니다. 업무 등록에서 실제 업무/연습을 구분합니다. 평가에는 별도 대화·작업 공간과 제한된 QA 도구만 제공하며 정답은 분리합니다. 경력은 프로젝트별로 표시하고 과거 평가 조건을 보존합니다.

실제 전이 과제 1개의 A/B/C 비교를 완료했습니다. 세 조건 모두 계약 결함 1개를 발견했고 C의 우위는 확인되지 않았습니다. 12개 전체 비교와 사람 검수 시간 측정은 미완료입니다. [경험 기능 사용법·실제 검증 결과](docs/EXPERIENCE-VALIDATION.md)를 확인하세요.

## 실행

Node.js 24 이상, Git, Codex CLI가 필요합니다. Windows에서 검증한 Codex는 0.153.4입니다.

```powershell
cd ai-company
npm install
./start-company.ps1
```

스크립트는 실행기를 숨김 프로세스로 시작하고 웹 서버를 켭니다. 주소는 http://127.0.0.1:4310 입니다. 웹 서버를 종료해도 숨김 실행기는 계속 동작합니다. 직원 실행 중지는 앱의 **전체 중지**를 사용하세요.

직접 실행하려면 별도 터미널 두 개를 사용합니다.

```powershell
# 터미널 1: UI/API
npm run dev
# 터미널 2: 영구 큐 실행기
npm run runner
```

프로덕션 UI는 `npm run build` 후 `npm start`이며 실행기는 별도로 유지합니다. 두 프로세스는 같은 `COMPANY_DATA_DIR`를 사용합니다. PC 종료·절전 중에는 진행되지 않습니다. Windows 부팅 자동 등록은 하지 않습니다.

## 처음 설정

1. **직원 채용**: 11개 직무 × 3개 가상 프로필을 면접·비교하고 직접 채용합니다. 최종 채용은 대표만 결정합니다.
2. **프로젝트**: 이름, Git 최상위 폴더, 기술 스택, 모델, QA 명령, 변경 허용 경로와 누적 호출·토큰 한도를 설정합니다. PO·CTO·QA와 업무에 필요한 개발자를 배정하고 개발자에게 쓰기 권한을 줍니다. 토큰 한도를 비우면 명시적인 무제한이며 호출 수·실행 시간·중지 제어는 계속 적용됩니다.
3. **자율 운영**: 목표·완료 기준·우선순위·허용 분류·업무 범위를 저장합니다. 동시 업무 수, 재시도, 업무/턴/운영 시간, 호출 수와 점검 간격을 정합니다. 적용 프로젝트·범위·한도를 확인한 뒤 시작합니다.
4. **자료함**: 실제 고객 피드백, 정책, 회계 내역을 등록합니다. 마케팅·회계 업무는 연결 자료 없이는 정보 대기로 멈춥니다.
5. **업무 보드**: 자율 운영 중 생성한 업무는 자동 처리합니다. 자율 운영을 켜지 않았을 때는 실행 요청 버튼을 사용합니다. 대화에서 관련 업무와 결과로 이동할 수 있습니다.

QA는 대표가 등록한 명령을 읽기 전용·네트워크 차단 sandbox에서 실행합니다. QA에서 패키지를 설치하거나 테스트 파일을 수정하지 않습니다. 스냅샷은 ignored `node_modules`를 복사하지 않으므로 외부 의존성이 필요한 프로젝트는 별도 준비가 필요합니다.

## 협업과 상태

코드 업무는 PO 요구사항 → CTO 분배 → 필요한 전문 검토 → 선택된 개발자 → QA → CTO 최종 검토로 진행합니다. QA가 테스트 실패나 완료 기준 미충족을 발견하면 실제 재현 명령·출력을 첨부해 수정 요청을 전달합니다. 수정 회차마다 새 개발 worktree에서 작업하고 다시 통합·QA합니다. 대표의 결과 수정 요청은 검증된 부모 결과의 정확한 커밋에서 후속 작업을 만들고 원본 근거를 보존합니다.

화면 개선은 디자이너, DB 변경은 DB 엔지니어, 요구사항/문서는 기획자가 참여합니다. 마케팅·회계·HR은 실제 자료에 근거한 문서 업무를 수행합니다. HR에는 해당 프로젝트 실행 이력이 제공되며 평가·채용 제안만 작성합니다. 이번 실증에서 모든 직무를 실제 모델로 검증하지는 않았습니다.

메시지는 프로젝트·업무·발신자·수신자·Run에 연결됩니다. 정보가 필요한 직원은 동료에게 질문하고 수신자만 별도 맥락에서 호출됩니다. 답변 도착 시 막힌 업무를 재검토합니다. 질문 연쇄에도 한도가 있습니다. 일반 채널 메시지는 기록과 운영 점검을 깨우며, 특정 업무 질문은 업무/수신자 API를 사용합니다. 진행 중인 모델 턴에 즉시 끼어드는 기능은 없습니다.

| 상태 | 의미 |
|---|---|
| 대기 | 큐 또는 선행 업무 결과 대기 |
| 실행 중 | 직원/검증 실행 중 |
| 정보 대기 | 자료·직원 배정·응답 필요 |
| 승인 대기 | 범위 밖 제안, 충돌, 외부 행동 |
| 일시정지 | 대표 중지 또는 호출·시간·토큰 한도 |
| 검토 대기 | 구현·QA·CTO 검토 후 대표 확인 대기 |
| 완료 | 대표가 검증된 결과 확인 |
| 실패 | 재시도 한도 도달 또는 실행 오류 |
| 취소 | 대표 취소 |

구현, 검증, 대표 검토, 배포 상태는 별도입니다. 검토 대기/완료는 배포 완료가 아닙니다. 외부 발송·지출·서비스 배포·운영 데이터 삭제·권한 확대는 결정함에 남깁니다. 외부 실행 커넥터가 없어 승인 기록만으로 실행하지 않습니다. 기술 판단은 CTO, 우선순위는 PO가 담당하며 미해결 충돌은 근거·선택지와 함께 결정함에 남깁니다.

## 데이터·코드 분리

회사 공통 데이터는 직무·지원자·채용 직원·공통 지침·전체 한도입니다. 목표·자료·기억·메시지·업무·결정·실행·작업 큐·코드 공간은 프로젝트별로 분리됩니다. 조회·수정은 SQLite `(kind, scope, id)` 기준입니다.

원본 Git checkout과 index는 수정하지 않습니다. 별도 clone에 HEAD·기존 tracked diff·일반 미추적 파일을 스냅샷하며 비밀 파일과 ignored 파일은 제외합니다. 개발 worktree와 브랜치는 직원마다 다릅니다. 한 업무의 개발자는 순차 작업하며 다른 업무는 프로젝트 설정 내에서 동시 실행합니다. 실행기 전체 동시 상한은 4개입니다.

통합은 허용 경로 검사 후 fast-forward로 수행합니다. 같은 원본에서 출발한 다른 업무의 결과와 파일이 겹치면 충돌 결정으로 남깁니다. 결과 위치·브랜치·변경 파일·검증 출력·실행 ID와 `evidence.json`이 완료 근거입니다. 원본 병합·push·배포는 하지 않습니다.

```powershell
# 실제 결과에 표시된 경로/브랜치로 치환
git -C '<원본 저장소>' fetch '<통합 저장소>' '<검토 브랜치>:<검토 브랜치>'
```

## 지속 실행과 복구

웹 서버는 SQLite 큐만 작성하고 실행기는 독립 프로세스로 동작합니다. 업무 생성·동료 메시지·선행 완료·설정 점검 시간에 필요한 직원만 호출합니다. 할 일이 없으면 대기합니다.

하나의 실행기가 `runner.lock`을 소유합니다. 큐 claim과 계획 발행은 트랜잭션으로 처리하며 단계마다 Run·Thread·Turn·보고·커밋을 저장합니다. 재시작 시 작업 공간과 중단 턴을 `thread/read`로 확인합니다. 완료 응답과 커밋은 재사용하며 상태를 확인하지 못하면 정보 대기로 남깁니다. 불완전 클론 준비 폴더는 보존하고 새 준비 폴더를 사용합니다.

완료 업무는 다시 큐에 넣지 않습니다. 정상 종료는 현재 실행을 중단하고 큐에 남깁니다. 전원 차단 직전 명령 효과까지 정확히 한 번만 발생한다고 일반적으로 보장하지는 않습니다. 기존 버전에서 중단된 업무는 수동 확인이 필요할 수 있습니다.

## 인증·사용량·권한

기존 Codex ChatGPT 로그인을 사용합니다. `codex login`으로 로그인하며 비밀번호·키를 화면이나 저장소에 넣지 않습니다. 이 방식은 계정 Codex 한도를 사용합니다. API 키 인증을 별도로 선택하면 OpenAI Platform 사용량 과금이 적용되며 구독과 별개입니다. 현재 앱은 API 키를 요구하지 않습니다.

토큰 이벤트 누적 차이를 기록하여 Thread 재개 시 중복 합산하지 않습니다. 이전 버전의 `last`만 있는 기록은 그 값으로 표시합니다. 시작 실패·중단·재시도도 호출 수에 포함합니다. 금액을 추정하지 않으며 미수신 토큰은 미확인으로 표시합니다.

호출 한도는 새 모델 턴 시작 전, 시간 한도는 타이머, 토큰 한도는 사용량 알림 수신 즉시 중단 요청으로 적용합니다. 마지막 호출의 사용량은 상한을 초과할 수 있으므로 **정확한 토큰/금액 hard cap은 아닙니다.** 일시정지·재개는 누적 호출·시간·토큰을 초기화하지 않습니다. 한도 변경과 재개는 대표가 결정합니다.

App Server 0.153.4의 이름 있는 `permissions` 프로필을 사용합니다. 네트워크·웹 검색·앱/플러그인·설정된 MCP는 자동 실행에서 끕니다. 다른 등록 프로젝트와 회사 SQLite 파일은 명시적으로 읽기를 차단합니다. 실제 Windows 검사에서 다른 프로젝트 읽기·회사 DB 읽기·읽기 전용 쓰기가 모두 `EPERM`으로 차단됐습니다.

기본 `:root=deny`만으로 이 환경의 모든 파일 읽기가 차단되지는 않았습니다. 등록되지 않은 디스크 전체와 동일 OS 계정까지 격리하는 신뢰 경계는 아닙니다. 서로 신뢰하지 않는 저장소에는 별도 OS 사용자/컨테이너 실행기가 필요합니다. `allowedPaths`는 통합 전 검사이며 파일별 실시간 쓰기 경계가 아닙니다.

공식 문서: [App Server](https://learn.chatgpt.com/docs/app-server), [권한 프로필](https://learn.chatgpt.com/docs/permissions), [인증](https://learn.chatgpt.com/docs/auth). 설치된 실행 파일의 생성 스키마와 함께 확인했습니다.

## 보관·검증

데이터는 `.local/data`에 저장합니다. 두 프로세스를 모두 종료하고 이 폴더를 백업하세요. `.local`과 인증 정보는 Git에 포함하지 않습니다. `COMPANY_DATA_DIR`는 데이터 위치, `PORT`는 웹 포트, `COMPANY_CODEX_BIN`은 CLI 경로, `COMPANY_API_TOKEN`은 선택적 로컬 Jarvis 인증 값입니다. 값은 OS 환경에서 주입합니다.

```powershell
npm run verify                     # 타입 검사 + 재현 테스트 + 빌드
node tests/sandbox-validation.mjs   # 실제 sandbox 검사, 모델 호출 없음
npm run validate:live               # 실제 Codex 사용량 발생
```

재현 테스트만 가상 어댑터를 사용하고 프로덕션은 실제 Codex에 연결합니다. 실증 실패와 미완료 사항도 [검증 기록](docs/AUTONOMY-VALIDATION.md)에 남겼습니다. 레슨퀘스트는 이 컴퓨터에 없어 직접 검증하지 못했습니다. 공통 코드에 이름·경로·스택을 하드코딩하지 않았습니다. Vercel 즉시 배포나 WorkAdventure 연동은 이번 범위가 아닙니다.
