# Rain Company — 독립형 AI 회사 운영 앱

여러 프로젝트에서 재사용하는 로컬 AI 회사 앱입니다. 연결 프로젝트가 없어도 실행·채용·면접·회사 공통 대화가 가능합니다. 한국어 UI를 제공합니다.

## 시작하기

Node.js 24 이상, Git, Codex CLI가 필요합니다.

```powershell
cd ai-company
npm install
npm run dev
```

브라우저에서 http://127.0.0.1:4310 을 엽니다. 배포 빌드 실행은 `npm run build` 후 `npm start`입니다. PowerShell에서 `./start-company.ps1`로도 실행할 수 있습니다.

1. **직원 채용**: 11개 직무 × 3개 초기 가상 프로필을 제공합니다. 성격·업무 방식·강점·약점은 생성된 템플릿이며 실제 평가 결과가 아닙니다. 면접과 동일 과제 비교는 실제 Codex 실행입니다. 채용은 대표가 직접 선택합니다.
2. **프로젝트**: 이름과 목표부터 등록할 수 있습니다. 개발 전에 Git 최상위 폴더, 기술 스택, QA 명령을 설정하세요. QA 명령은 필요한 의존성 설치를 포함할 수 있습니다. Windows PowerShell에서 실행합니다.
3. **팀 배정**: PO·CTO·백엔드·프런트엔드·QA를 배정하세요. 개발자 2명에게 코드 쓰기 권한이 필요합니다. 나머지 6개 직무는 채용·면접·개별 대화가 가능하고 자동 개발 파이프라인에는 포함되지 않습니다.
4. **업무 보드**: 작은 요청과 완료 조건을 등록하고 실행합니다. 등록만으로는 Codex를 실행하지 않습니다.
5. **결과 검토**: 실제 변경 파일, diff, QA 명령/종료 코드/출력, 역할별 Run·Thread·Turn ID와 이벤트를 확인합니다.
6. **사내 채팅**: 직원의 실행 보고와 인계가 일반 채널에 남습니다. 대표가 일반 채널에 작성한 최근 메시지는 다음 업무 단계에 반영됩니다. 진행 중인 턴에 즉시 끼어드는 기능은 아직 없습니다.

## 공통 데이터와 프로젝트 데이터

| 회사 공통 | 프로젝트마다 독립 |
|---|---|
| 11개 직무 정의, 가상 지원자 | 목표, 기술 스택, 저장소 경로, QA 명령 |
| 채용한 직원 기본 프로필·개인 지침 | 담당 직원, 읽기/쓰기 권한, 변경 허용 경로 |
| 회사 이름·운영 규칙·전체 한도 | 대화, Codex Thread, Run, 실행 이벤트 |
| 공통 면접·회사 운영 대화 | 업무, 단계 체크포인트, 기억, 테스트 결과 |
| 회사 전체 중지 상태 | 프로젝트 실행 횟수·토큰 예산·실제 사용량 |
| | 업무별 통합 저장소와 개발자별 Git worktree |

SQLite의 모든 업무 데이터 조회는 `(kind, scope, id)`로 제한됩니다. `scope=company`는 명시적인 회사 공통 대화/면접 공간입니다. 다른 프로젝트의 기록은 프롬프트에 넣지 않습니다. 직원 설정을 변경하면 후속 실행의 지침에 반영됩니다. 해당 프로젝트에서 완료한 업무의 인계 내용은 프로젝트 기억으로 저장되어 다음 실행에서 사용됩니다.

원본 Git checkout은 수정하지 않습니다. 별도 clone에 HEAD와 미완료 tracked diff, 일반 미추적 파일을 스냅샷합니다. ignored 파일과 비밀 정보로 보이는 미추적 파일은 복사하지 않습니다. 추적 중인 비밀 파일이 있으면 연결 작업을 차단합니다. 개발자는 통합 HEAD에서 각자의 worktree를 만들고 순차 실행합니다. 개발자 변경은 허용 경로 검사를 통과한 뒤 커밋하고 fast-forward로 통합합니다. 대표의 기존 index/staged/unstaged 상태를 건드리지 않습니다.

검토 브랜치는 결과에 표시된 **별도 통합 저장소**에 있습니다. 원본으로 가져오려면 실제 결과의 경로·브랜치를 사용하세요. 아래 꺾쇠 부분은 치환해야 합니다.

```powershell
git -C '<원본 저장소>' fetch '<결과에 표시된 통합 저장소>' '<검토 브랜치>:<검토 브랜치>'
```

원본 병합, 원격 push, 배포는 자동으로 수행하지 않습니다.

## 실행 방식과 인증·과금

2026-09-10 공식 문서와 설치된 Codex CLI **0.153.4**의 생성 스키마를 확인했습니다. 대화 기록, 인증 상태, 스트리밍 이벤트, 중지 API를 직접 다루기 위해 **Codex App Server의 로컬 stdio JSON-RPC**를 선택했습니다. 단순 배치 작업에는 Codex SDK도 적합하지만 이 앱의 대화 중심 UI에는 App Server가 더 직접적입니다.

- 기존 ChatGPT 로그인: Codex가 자신의 저장소에서 인증을 읽습니다. 앱은 토큰·비밀번호를 읽어 화면에 표시하거나 DB에 복사하지 않습니다. 이번 환경에서는 `codex login status`와 `account/read`로 ChatGPT 로그인을 확인했습니다. 이 실행은 계정의 Codex 한도/크레딧을 사용합니다. 직원마다 별도 구독이 생기지 않습니다.
- 로그인 없을 때: 로컬 터미널에서 `codex login`을 실행하고 브라우저 로그인 절차를 완료하세요. 채팅에 비밀번호·토큰·키를 붙여넣지 마세요.
- API 키 인증: 명시적으로 API 키 방식으로 로그인하면 OpenAI Platform에서 별도 사용량 기반 과금됩니다. ChatGPT 구독료와 별개입니다. 현재 앱은 API 키를 요구하지 않습니다. 키 인증이 필요하면 OS 비밀 저장소나 터미널의 안전한 입력을 이용하고 CLI의 stdin 로그인 방식을 사용하세요. 코드나 저장소에 키를 넣지 마세요.
- 이 앱의 토큰 수는 실제 실행 이벤트에서 수신한 값입니다. **금액 추정이나 청구 내역이 아닙니다.** 누락된 사용량은 미확인으로 표시합니다. 계정 한도에는 이 앱 밖에서 쓴 Codex 사용량도 포함됩니다.
- 회사 전체와 프로젝트의 실행 횟수·토큰 예산을 다음 실행 **시작 전에** 검사합니다. 한 번 시작된 턴의 토큰 사용은 예산을 초과할 수 있습니다. 요청 중간의 정밀 토큰/금액 hard cap은 아닙니다. 실패한 시도도 실행 횟수에 포함합니다. 각 에이전트 실행은 최대 10분, QA 명령은 최대 3분입니다.

공식 근거: [Codex SDK](https://learn.chatgpt.com/docs/codex-sdk), [App Server](https://learn.chatgpt.com/docs/app-server), [인증과 과금 방식](https://learn.chatgpt.com/docs/auth), [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox).

## 중지·복구와 한계

- 전체 중지는 DB에 먼저 저장하고 현재 앱이 시작한 프로세스에 취소를 보냅니다. Windows는 자식 프로세스 트리도 종료합니다. 다시 허용해도 업무를 자동 시작하지 않습니다. 보드에서 **이어서 실행**을 선택하세요.
- 서버 재시작 시 실행 중이던 Run은 interrupted, 업무는 paused로 복구합니다. 완료 단계는 재실행하지 않습니다. 미완료 단계는 저장된 Codex Thread와 worktree에서 재개합니다.
- 정상 종료는 취소를 전달합니다. OS 강제 종료/전원 차단은 마지막 기록 사이의 작업이 남을 수 있습니다. 재개 시 작업 공간과 결과를 확인하세요. 저장소 준비 도중 중단되었으면 원본을 보존한 채 새 업무로 재시도하도록 안내합니다.
- 한 회사 앱 프로세스에서 동시에 한 대화 또는 개발 업무를 실행합니다. 개발자 작업 공간은 분리되어 있지만 현재 버전의 개발 순서는 백엔드 → 프런트엔드입니다.
- 로컬 단일 사용자 도구입니다. API는 loopback에만 바인딩하고 Host/Origin 검사, HttpOnly SameSite 세션을 사용합니다. 인터넷에 직접 노출하지 마세요.
- 프로젝트 분리는 DB/API/프롬프트/작업 디렉터리 단위의 논리적 분리입니다. Codex sandbox로 쓰기를 worktree에 제한하고 통합 전에 경로를 검사합니다. 설치된 Windows sandbox의 읽기 범위와 같은 OS 계정의 접근까지 별도 보안 경계로 격리하지는 않습니다. 서로 불신하는 프로젝트의 강한 보안 격리가 필요하면 별도 OS 사용자/컨테이너 runner가 필요합니다.
- `allowedPaths`는 **통합 전에 변경을 거르는 규칙**입니다. 폴더별 실시간 파일시스템 ACL을 생성하지 않습니다. 네트워크 옵션은 에이전트 sandbox에 적용됩니다. 대표가 설정한 QA 명령은 신뢰된 로컬 명령으로 서버 권한에서 실행되므로 직접 검토해서 등록하세요.
- 프로젝트 의존성/외부 서비스는 자동으로 제공되지 않습니다. QA 명령과 저장소 설정으로 준비합니다. 이 앱 자체에는 외부 DB나 별도 유료 API가 필요하지 않습니다.
- 레슨퀘스트는 현재 컴퓨터에 없어 검사·변경하지 않았습니다. 실제 협업은 별도 검증용 프로젝트에서 수행했습니다. 레슨퀘스트 이름/경로/스택은 공통 런타임에 하드코딩하지 않았습니다.

## 데이터와 환경 설정

기본 DB와 작업 공간은 `.local/data`에 저장됩니다. `.local`은 Git에서 제외합니다. 앱을 종료한 뒤 폴더 전체를 백업하세요. 실행 이벤트와 Codex 자체 기록에는 프로젝트 내용이 포함될 수 있습니다.

| 환경 변수 | 용도 |
|---|---|
| `PORT` | HTTP 포트, 기본 4310 |
| `COMPANY_DATA_DIR` | 별도 DB/작업 공간 루트 |
| `COMPANY_CODEX_BIN` | 자동 발견되지 않을 때 Codex 실행 파일 절대 경로 |
| `COMPANY_API_TOKEN` | 선택 사항. 로컬 Jarvis 호출용 bearer 인증. OS 비밀 저장소에서 주입 |

Vercel CLI는 현재 설치되어 있지 않습니다. 향후 Vercel 환경/배포/로그 기능이 필요하면 `npm i -g vercel` 설치를 권장합니다. 이 앱의 로컬 Codex·Git runner를 Vercel 함수로 그대로 배포하는 구조는 아닙니다.

## 검증

```powershell
npm run check
npm test
npm run build
```

자동 테스트는 격리 저장소, 미완료 변경 보존, 인증/CSRF, 예산, 중지/재개, 범위 분리를 검증합니다. 자동 테스트의 Codex는 명시적인 테스트 어댑터입니다. 실제 통합 검증은 `node tests/live-validation.mjs`로 별도 실행하며 **실제 Codex 한도를 사용**합니다. 실제 검증 결과는 `docs/VALIDATION.md`를 참고하세요.
